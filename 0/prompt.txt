## 2. Timeline component (`LaunchTimeline.tsx`, plain SVG, no new library)

**Axis.** It runs from `min(now, first shift start)` to Sun 20:00, plus a gutter of about 12% width past the truck line labelled "Too late", which is not to scale. The scale is piecewise: shift hours are full width and nights are drawn at 25% width, greyed with "no shift". Past time is faded, and a `now` hairline uses `state.now` plus the existing offset clock. The truck line is a thick ink rule with "Trucks 20:00" written on it.

**Edition lanes** come from `strip[]` (`label`, `level`).
- If `breaks_first.stops_at` is before launch, draw a solid bar in the level colour up to `stops_at`, then red hatching up to 20:00. The label reads "stops Sun 17:00 · {copies_at_risk} short".
- Otherwise draw a blue bar up to the finish time with "{slack_hours} h spare" after it. Collector's with 2 h spare will look visibly tight, which is the point.
- Bars are clipped to shift windows, so the line never appears to run at night.

**Markers.** Cards are matched to a lane by `card.edition`; cards without an edition go to the Inbound lane.
- ◆ `card.deadline`, labelled "Decide by 10:00". It turns red within 3 h, using the existing `until()`.
- ▼ `card.runs_dry`.
- Only the `breaks_first.card` marker gets a permanent label. All others show their label on hover, to avoid label collisions.

**Inbound lane** comes from `shipments[]`.
- A dot sits at `eta`, coloured by `level`. Silent shipments are hollow grey with "silent {silent_hours} h".
- If `eta` is after 20:00, the dot goes into the gutter, stacked and red, with the real date ("Tue 24 Nov"). That is how the 20,000 game cards visibly fall past the line.
- If `eta` is missing, the dot goes in a "No ETA" chip at the lane start.

**Interaction.**
- Hovering a marker shows a one-line tooltip and highlights the matching card. A dot is linked to a card when `card.shipment === shipment.id`.
- Clicking selects the card (`selectedId`), which then fills the main column.
- In the other direction, hovering a card highlights its markers. Reuse the existing `onHover` pattern, but key it by card id.

**Missing data and fallbacks.** `State` has no shift windows, no launch time, and no finish time per edition. In `build_state`, add:
```
clock: { launch, windows:[[s,e]], editions:[{edition, finishes_at}] }
```
This is about 15 lines and uses `PackClock.windows` and `after_packing_hours(cur, remaining/rate)`. On the frontend, keep a constant fallback (Sat 06–22, Sun 06–20, launch Sun 20:00). If `finishes_at` is missing, compute it as the 20:00 line minus `slack_hours`. If both are missing, draw the bar to the line, dashed, with no claim attached.
