## 1. The model: the LLM writes a spec, a compiler writes the code

**Recommendation:** the LLM returns only a structured spec. A small Python compiler (about 40 lines in `routines.py`) turns that spec into the same `soony` Python, which still runs in the Monty sandbox. "Show the code" stays; it now shows compiled code.

Why this and not "the structure describes the LLM's code":
- **Safety.** Drag-and-drop and text edits change data, never code. The "costs money comes to you" rule is added by the compiler, so it cannot be left out.
- **Demo reliability.** The sandbox can't reject a draft anymore, so the repair round goes away. Before/after is a plain JSON comparison.
- **Time.** A description-only structure would drift from the code after the first edit, and the screen would show something the routine doesn't do.

Spec shape (replaces `code` in the writer prompt's JSON; `name` and `description` stay):
```json
{"when":[{"id":"c1","field":"evidence|option_action|option_to|supplier_name|supplier_country|kind",
          "op":"contains|is|in","value":"ready for pick-up","text":"the papers say goods are ready for pick-up"}],
 "then":[{"id":"s1","do":"carry_out","match":{"to":"DC site lead","action_contains":"collect"},
          "text":"Send the collect message to the DC site lead"},
         {"id":"s2","do":"notify","channel":"phone|teams|both","text":"Tell me on Teams"},
         {"id":"s3","do":"log","text":"Note it in the history"}]}
```
- Conditions are combined with AND. Every card is handled once (the compiler always uses `first_time`).
- The "costs money" rule is not in the spec; it is always added.
- IDs must stay stable across edits; the prompt says "keep ids of unchanged items".

Two backend gaps:
- `notify()` always sends both phone and Teams. It needs a `channel` argument, otherwise "also tell me on Teams" changes nothing.
- "Only for Polish suppliers" needs `supplier_country` in `_card_view` (from master data). Without it, the editor must answer "I can't filter by country yet" rather than guess.

## 2. How one routine looks (`RoutineFlow`)

Card frame: `rounded-xl border border-line bg-white p-4`.
- **Header:** name (`text-[16px] font-bold`) and a real switch (`h-5 w-9 rounded-full`, `bg-ok` when on, `bg-line` when off). It replaces the On/Off pill, which looks like a button.
- **Stats line** (`text-sm text-ink-3`): "Handled 3 cards · Last ran 03:39 · Nothing to do". Add a `handled` counter on the backend, because `runs` keeps only the last 20.
- **Blocks:** stacked vertically, joined by a connector (`ml-6 h-3 w-px bg-line`). Each block is `rounded-lg border border-line px-3 py-2.5 text-[15px]` with a label column `w-14 text-xs font-bold uppercase tracking-wide`.
  - **When** (label `text-ink-3`): conditions as chips, `rounded-md bg-panel px-2 py-1 text-sm ring-1 ring-line`. Show the `text` phrase, never the field names.
  - **Then** (label `text-ok`): one row per step with a lucide icon:
    - `Send` for "carry out"
    - `Smartphone` / `MessageSquare` for "tell me" (phone / Teams)
    - `NotebookPen` for the log
  - **Always** (fixed, `border-dashed bg-panel`, `Lock` icon): "Costs money? It comes to you to decide." No delete button and not draggable.
- **Footer:** "Run now" and "Delete" (keep the current ones), then "Show the code", collapsed.

## 3. Editing (about 3 hours, in this order)

**Build (45 min): the change box.**
- Under the blocks: an input (`h-10 rounded-lg border-line`) with placeholder "Change it in your words, e.g. “also tell me on Teams”", plus a small button "Change".
- New endpoint `POST /api/routines/{id}/edit {instruction}`. The LLM gets the old spec and the allowed fields, returns a new spec; the server compiles it, does a dry run, and returns `{before, after, preview}`.
- The client compares blocks by ID:
  - Added: `bg-ok/5 ring-1 ring-ok/40` with a small "New" tag.
  - Removed: `opacity-60 line-through` with a "Removed" tag in `text-stop`.
  - Changed: the old phrase struck through, then the new one.
- Below that, "Test on today's inbox:" with the existing `Steps` component. Buttons: "Apply change" (disabled if the test failed) and "Keep as is".

**Build (30 min): direct manipulation, no library.**
- An × on hover removes a condition chip or a step (re-compile, then the same review step before saving).
- Native HTML5 drag-and-drop (`draggable`, `onDragOver`) reorders "Then" steps.
- A small palette under "Then" with three chips you can drag or click: "Tell me on my phone", "Tell me on Teams", "Note it in the history".

**Don't build:**
- A node-graph or canvas editor.
- Dragging new conditions in (they need value entry; use the change box).
- Picking a different carry-out target by dragging.
- Editable Python.
- Changing a routine live by voice during the call.
